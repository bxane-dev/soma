# Soma auto updater

Soma uses Tauri's signed updater and GitHub Releases from:

`https://github.com/bxane-dev/soma`

The packaged app checks:

`https://github.com/bxane-dev/soma/releases/latest/download/latest.json`

on launch and every six hours.

## Why signing is required

Tauri verifies updater packages before installing them. The signing private key must never be committed to this repository.

## One-time key setup

From a trusted machine after installing dependencies:

```bash
npm install
npm run tauri signer generate -- -w ~/.tauri/soma.key
```

Back up the generated private key securely. Losing it prevents existing Soma installs from trusting future updates.

Add these GitHub Actions repository secrets:

- `TAURI_SIGNING_PRIVATE_KEY` — contents of the generated private key
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — the key password, if one was set
- `TAURI_UPDATER_PUBLIC_KEY` — the public key output generated by the Tauri signer

The public key is safe to expose, but the workflow accepts it as a secret so release builds can inject it without editing source files.

## Publishing an update

1. Update the version in both `package.json` and `src-tauri/tauri.conf.json`.
2. Commit the release.
3. Create and push a tag such as `v0.2.0`.
4. GitHub Actions builds installers, updater artifacts and `latest.json`.
5. Existing Soma installs see the new stable version on their next update check.

## Security

- Updater transport uses HTTPS.
- The GitHub Releases endpoint is fixed in app configuration.
- Tauri verifies the downloaded update signature before installation.
- Windows uses passive installer mode.
- The private updater signing key is never stored in the repository.

The checked-in updater public key is a non-production development placeholder. Production release builds replace it using `TAURI_UPDATER_PUBLIC_KEY`.
